# 文献对照:核心点与区分度是否还成立

对照两篇同期工作:SEE(arXiv 2608.06931v1,2026-08-07)与 OPT-BENCH(arXiv 2605.08904)。
结论分两半 —— **方法论上的核心点成立且比对手更锋利,但"区分度"这个词在领域里的用法上,我们的证据是零。**

## SEE:不同的轴,但有一个值得警惕的呼应

SEE 是专家从同行评议文献与真实实验流程中出题的多模态问答基准,覆盖化学、生物、材料。
19 个 MLLM,最好 48.7% 准确率,允许用工具后 52.7%。

它与我们不在同一条轴上:静态问答 vs 迭代改进一个可执行产物。这一点上我们的定位没有被侵占。

但它的核心发现值得警惕:模型**无法把工具取回的信息约束在原始实验证据的边界内**,
所以"给更多信息"并不带来更好的科学推理 —— 加了工具只从 48.7% 到 52.7%。

这与我们测到的东西是同一个现象的两种形态。我们在 6 个任务上测到**反馈有害**
(Truss −0.37、RANSCalibration、HeatExchangerDesign 方向明确,另 3 个单 seed),
机制是开环靠独立抽样撞到长右尾而反馈臂锚死在 incumbent 上。SEE 的"更多信息不等于更好推理"
和我们的"更多反馈有时更差"指向同一件事:**把外部信息喂回去这个动作本身不是免费的。**

这是个交叉验证,不是威胁。

## OPT-BENCH:正面竞争,而且它已经有了对照臂

OPT-BENCH(20 个机器学习任务 + 10 个 NP-hard 问题,19 个模型,3B–235B)明确要测
"内在自优化 —— 利用环境反馈爬升性能景观的能力"。这与我们的主张正面重合。

它已经做的:

- **无反馈对照**:"Random Rollout: 无历史上下文、无记忆地独立生成解"。这是对照臂的思路,与我们的
  `selection_blind` 同源。
- **锚定归一**:`(M_current − M_initial)/(M_expert − M_initial)`,以专家基线为锚,**未显式封顶**。
- **区分度**:ML 任务上 Expert Gap 在 0.15–0.61(闭源模型,20 步);NP 任务 0.47–0.79。

它没有做的,恰好是我们做了的:

| 我们有 | OPT-BENCH |
|---|---|
| 种子配对、预算匹配的 Δ,带留一法稳健性检查 | Win Counts 对随机 rollout,非配对;论文自述"数据结构无法直接比较" |
| 交叉点分析(Δ 随预算的形状,best-of-N 何时反超) | 跑了 5/10/20 步,但没有交叉点分析 |
| 饱和判据(对照必须已被 best-of-N 打穿才算数) | 无饱和分析 |
| 反馈有害的明确报告(6 个任务) | 未报告任何反馈变差的案例 |
| 发现类三轴分报(机制/误发现/拒绝) | 纯优化 |
| 实质性阈值(差距须相对分数量级足够大) | 无 |

所以方法论上我们不但成立,而且**比它锋利**。特别是"对照必须饱和"这一条 —— OPT-BENCH 若不做,
它测到的 Expert Gap 就可能是所选步数的产物,这正是我们在分子任务上实测到的交叉点(budget 7.8)。

## 区分度:领域说的是跨模型,而我们是 N=1

这是必须直说的一条。

"区分度"在 SEE 与 OPT-BENCH 里指的是**同一批任务在不同模型上拉开的分数差**:
SEE 19 个 MLLM 撑起 48.7% 的天花板,OPT-BENCH 19 个模型撑起 0.15–0.61 的 Expert Gap 跨度。

我们的运行清单:

| | 数量 |
|---|---:|
| gpt-5.5 | 229 次 |
| 模型未记录(补记可读模型条件之前的旧清单) | 222 次 |
| greedy_rewrite | 424 次 |
| openevolve | 24 次 |
| abmcts / shinkaevolve | 2 / 1 次 |

**一个模型、一个搜索器。** 我们做过的所有"区分度"工作都是任务对任务的
(这个任务还有没有头部空间),没有一条是模型对模型的。所以严格讲,
我们目前无法回答"这套题库能不能区分模型强弱"这个问题 —— 不是答案不好,是没有数据。

而且交叉点已被证明是任务×搜索器的性质,这意味着单搜索器的结论**不可外推**:
我们说 QuantumErrorDecoder 合格,严格只对 gpt-5.5 + greedy_rewrite 成立。

## 还成立的核心点

1. **两种形式(科学优化 / 科学发现)**。SEE 是问答,OPT-BENCH 是纯优化。带社区 oracle 的
   发现类任务(SpinSystemInference)在这两篇里都没有对应物。
2. **可执行产物 + 冻结 oracle**,而非文本作答或 LLM 评审。
3. **准入判据本身**。OPT-BENCH 有对照臂但没有把它变成准入门槛;我们把"对照必须饱和 +
   反馈必须持续拉开"写成了可复现的脚本,并用它否掉了自己 7 个 certified 任务。
4. **锚定在社区例程而非作者选的目标**。OPT-BENCH 用专家基线,方向一致;我们在 4 个任务上
   做到了用社区**例程**(评测时重算)而不只是一个数。

## 不再成立、或从未成立的

1. **"我们有区分度"** —— 没有跨模型证据,不能这么说。
2. **"我们比同期工作更早想到对照臂"** —— OPT-BENCH(2026-05)已经有 memory-less 对照,
   早于我这轮工作。我们的增量是配对、预算匹配、留一法与饱和判据,不是对照臂本身。
3. **题库规模的优势** —— 63 个任务里 56 个 clipped 且锚在作者选的目标上,12 个已打满。
   OPT-BENCH 只有 30 个环境但都带专家基线且未封顶。**可用的任务数我们并不占优。**

## 该做什么

**最高优先:跑第二个模型。** g450 上已有 `local.gpt56.yaml`。在 5 个已合格任务上跑
gpt-5.6 与 gpt-5.5 的配对,是唯一能把"区分度"从零变成有的动作,成本远低于新建任务。
没有这个,前面所有任务质量工作都无法回答审稿人第一个会问的问题。

**其次:第二个搜索器。** openevolve 只跑过 24 次。交叉点是任务×搜索器的性质,
单搜索器的合格判定不可外推。

**第三:把方法论增量写清楚。** 对照臂不是我们的原创,配对 + 饱和判据 + 交叉点 + 有害报告是。
这四条要作为方法贡献单独讲,否则会被读成 OPT-BENCH 的复制。

## 边界

SEE 与 OPT-BENCH 的细节来自摘要与全文抓取,未逐页核对表格。OPT-BENCH 的"未报告反馈有害"
是从其 Win Counts 结构推断的,不排除正文有我未抓到的分析。

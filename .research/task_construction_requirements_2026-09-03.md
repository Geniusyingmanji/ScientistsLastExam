# 造题要求(2026-09-03,首个应用案例:Physics/SuperconductorTcRecord v2)

来源:v1 版 `Physics/SuperconductorTcRecord` 用户审查后指出三条硬要求。这三条不是这一个任务的
一次性修补,而是往后任何"把人类科学家论文里的优化问题改造成 SLE 任务"都要过的门槛,记在这里
供后续任务复用。

## 三条要求

### 1. 优化条件要与论文里人类科学家的条件可比

任务里 agent 能操纵的变量、变量的取值范围、约束,必须能在被引用的论文里找到对应物,不能为了
"造出一个可搜索的空间"而凭空发明一个论文里不存在的维度。

v1 的违规:发明了一个连续掺杂比例 `x ∈ [0,1]`,而且给每个"世界"随机扰动一次隐藏最优点
(`x_opt`、`p_opt` 各世界不同)。真实论文里 H₃S / LaH₁₀ / YH₆ / YH₉ 都是接近固定化学计量比的
化合物,不存在"同一家族里连续可调的掺杂比例"这种旋钮;真实的"世界"只有一个,不存在"每次运行
重新抽一次隐藏物理"这回事。

修复方向:agent 能选的变量必须是论文里真实出现过的量——**是哪个化学计量比**(离散,论文里
明确列出的候选,比如 LaH₁₀ vs YH₆ vs YH₉,而不是连续插值出来的"家族内比例")、**压力**(论文里
报道的真实稳定/测量压力区间,而不是围绕一个随机中心的高斯"圆顶"),以及任务本身可以合理引入的、
论文之外但物理上真实存在的**工程约束**(比如不同实验室能达到的最高压力不同——金刚石对顶砧
和双级/环形砧的极限压力确实不同,这是真实、可引用的差异,可以作为"多组重复试验"的轴,而不是
去随机扰动物理本身)。

### 2. 优化目标要和论文里人类科学家的目标一致,尽量保留原目标

不要把论文的目标换成一个"更好造题"但科学含义不同的代理目标。论文里科学家优化的是**临界温度
Tc**(通过 Allen-Dynes/Eliashberg 从计算或测量得到的 λ、ω_log 算出来),任务的 `combined_score`
就应该直接对应这个量,不能换成别的东西。

在此基础上,**可以加一个次要指标用来给被评测者(agent)打分**——但这个次要指标必须是同一物理量
的自然延伸(比如对 Tc 的预测校准误差、置信度校准),不能引入和这个科学问题无关的变量(不能加
"代码风格""回答长度""创造力"这类东西)。次要指标必须和主分数分开报告,不能混进
`combined_score` 里稀释主目标。

### 3. 优化要难、要耗时,验证要快

真实科研里,"搜索"(结构预测、DFT 弛豫、声子计算)极其昂贵,而"验证"(拿到已知 λ、ω_log 后
用 Allen-Dynes 公式算 Tc)是解析式、秒算。任务要保留这个不对称性:

- agent 每次"探测"要计入预算,模拟真实计算/实验的代价——这个机制本身不违反第 1 条,因为"做一次
  测量要花钱/花时间"本身就是真实科研的一部分,不是凭空发明的游戏机制。
- 但探测所揭示的信息,必须对应论文里真实存在的**认知不确定性**,而不是对应一个凭空编的"世界随机
  扰动"。v2 的方案:真实存在的、有引用支持的"理论预测(谐波 DFT,systematically 偏高)vs. 实测/
  非谐修正后的真实值(通常更低,有的理论预测甚至从未被实验实现)"这个缺口,就是探测要揭示的东西——
  这既是真实科学现象(Kong et al. 2021 自己在摘要里写"measured Tc notably lower by ~30 K than
  predicted"),又天然给了 agent 一个"不能只背训练数据里的数字,必须主动验证"的理由。
- 最终打分(`evaluate()`)必须是对已提交答案的一次直接查表 + 公式计算,不能要求重新跑一遍搜索。

## 如何核查一个候选任务是否满足这三条

1. 列出 agent 能看到/能操纵的每一个变量,逐条问:这个变量在被引用的论文里是不是真实存在、真实
   报道过取值范围的东西?如果是造题者自己发明的连续插值维度,不合格。
2. `combined_score` 的公式和论文的优化目标做映射,应该能一一对应,不能有目标漂移。次要指标如果
   加了,检查它是不是同一物理量的自然延伸。
3. 确认 evaluate() 内部对候选提交的打分是查表/闭式计算,不依赖运行候选自己的搜索逻辑;确认
   candidate 侧的"探测"预算对应的是真实存在的、有引用支持的认知缺口,而不是纯游戏机制。

## Claim guard and scientific scope

The 32-state guard applies only to generic L* hypotheses. A verified family fit
may return a larger machine. Raising the guard alone does not improve either
graded split. That one seed is not a false-positive guarantee. A separate fixed
Linux CandidateProxy plan repeated the reference and a variant with both claim
and observation-table caps raised to 1024 over shifts 0 through 7. All 288 world
evaluations were valid. The reference made zero false claims; the larger-cap
variant made six, and its development/heldout means fell from 0.777778/0.71875
to 0.708333/0.6875. The [source-bound report](claim_guard_2026-09-12.json) gives
the plan and payload hashes. The original policies are unchanged; seed shifts
redraw observations, not mechanism families. This supports keeping the guard
as an empirical error control, and does not establish universal equivalence
from finite tests. Exact equivalence is established by the hidden scoring
oracle after submission.

The [CacheQuery paper](https://arxiv.org/html/1912.09770v2) supports the use of
cache-line abstractions and automata inference. Its guarantee depends on
deterministic policies and sufficiently discriminating tests. This package's
synthetic mechanisms, independent noisy outcomes and bounded hypothesis checks
remain its own modeling choices, requiring measured validation.

All 47 paper-catalog objectives and the pinned repository's 78 rows / 84 expanded
tasks were independently reviewed for objective, artifact and oracle overlap.
No same problem class was found; the closest systems entries optimize allocators,
database execution or CPU logic rather than identify a hidden replacement automaton.
The [source-indexed novelty record](novelty_2026-09-12.json) states the historical
95-entry snapshot limitation explicitly. It does not claim 95/95 coverage.

## Grid construction defect

The independent replay found two malformed strategies in the builder grid:
`blind_srrip_fp` and `blind_srrip_hp` each submit a machine above the public
1024-state cap in two worlds. Their original measurements have 16/18 valid worlds;
their zero scores are not evidence of shortcut difficulty. The builder JSONL did
not record per-world validity, hiding this distinction.

The ladder's common answer builder now refuses hypotheses above the public cap.
This changes only probe construction, not the task's evaluator or the fixed grid's
parameter choices. The original invalid observations are retained. A separately
bound [repair replay](grid_shape_repair_2026-09-12.json) evaluated each repaired
candidate twice: all four runs were valid in all 18 worlds, both full-metric
pairs matched exactly, and both methods scored zero on both splits. These are
new repaired-candidate observations, not relabeled original grid cells.

The optional builder `best K` routine also broke development-score ties using
heldout score. It now uses declared cell order for ties and does not read heldout
values. It requires one measured row per declared cell, rejects missing validity,
and selects only fully valid candidates. The grid records world validity and
restores observation seeds and caches even after an evaluation exception; callback
counts include failed candidates. Existing builder JSONL is preserved. It cannot
be reused for `best K` by inventing missing validity flags.

Four integrity fixtures exercise heldout perturbation/deletion invariance,
invalid-candidate exclusion, duplicate/missing/unmeasured cells, and seed/cache
restoration after a failure. They use synthetic control rows, not scientific data.
The independent 343-cell replay uses every frozen cell and never invokes `best K`.
After this repair, the clean `02189f6c` Linux tree ran all three task/research test
files: **25 passed, zero failed/skipped**, 63.12 seconds. The
[fixture receipt](linux_fixture_validation_2026-09-12.json) binds the full revision,

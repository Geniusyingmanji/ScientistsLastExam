# Discovery 的独立科学审阅约定

本文件规定 SLE 如何审阅**问题 → 竞争假设 → 实验或推导 → 证据 → 检验（必要时修订）→ 有适用范围的结论**。它是项目评测约定，不是某个学科通用的发现认证标准。规律、结构、机制、物质是结论类型；负面结果、排除一种解释、证据不足和空结论都可以是有效产出。

没有 GT 时，审阅依据是可追溯的观测、声明的假设、实验或推导及其论证边界，不是隐藏答案。程序化检查、代理方法审阅和独立领域审阅分别保存；不计算或汇总成科学发现总分。资料不足、协议不具备相应能力或尚无合适审阅者时，该项保持 `unassessed`。

## 三层工作分别记录

| 层次 | 执行者与工作 | 可记录的结果 | 不能代替的判断 |
| --- | --- | --- | --- |
| 过程核查 | 可信程序核对报告结构、事件顺序、冻结摘要、原生引用、计费和覆盖；确有重放时另记执行证据 | 哪项检查实际执行、输入版本、通过或失败、未执行与原因 | 科学问题价值、测量有效性、因果关系、新颖性 |
| 代理方法审阅 | 与候选执行分开的代理，检查已记录的方法、代码、计算和解释；如参与过实现或数据准备必须披露 | 有具体定位的方法疑点、可复核的计算说明、遗漏、限制与待领域确认的问题 | 独立领域专家意见、盲审、科学认证；模型代理不因使用另一个模型就自动具备独立性 |
| 独立领域审阅 | 明示相关领域能力及独立性的审阅者，在其实际可审范围内检查假设、测量、推断、替代解释与贡献 | 有证据、有理由、有适用范围的书面判断，以及未能判断的事项 | 对未查看资料或未评学科的背书；不能由前两层自动填为完成 |

一层发现的问题可以交给另一层核实，但不能复制其状态作为本层结论。字段齐全、区间相容、复合主张结构完整或引用合法，均不等于科学推理成立。代理方法意见另存，不回写原报告的八轴 `semantic_review`。独立领域意见同样保存为绑定原报告的外部审阅记录，保留原始状态和历史证据。

## 审阅开始前的声明

每份审阅先填写以下信息；没有声明时不称为“独立审阅”。

| 项目 | 必填内容 |
| --- | --- |
| 审阅对象 | Episode 文件字节 SHA-256、报告内摘要、schema/协议版本、源码与数据绑定；缺失项明确列出 |
| 审阅者 | 可追责的姓名或 ID、角色、相关领域或方法能力、审阅日期；代理另记模型 ID、提供方及其可验证程度，未知则明确未知 |
| 实际参与 | 是否编写任务、候选、评测器、数据准备、筛选规则、分析或既有报告；分别列明参与事项 |
| 已知信息 | 是否见过候选身份、其他运行、封存观测或已有审阅；不能事后把已经看过的信息称为盲审 |
| 审阅范围 | 实际读取的文件、事件、图表和外部文献；未获得的数据、仪器记录或专业能力 |
| 利益与独立性 | 与实现者、数据提供者、候选及结论的关系；独立性不足时按实际角色记录，不省略声明 |
| 执行边界 | 是否仅阅读、重算汇总、重放候选代码或独立采集数据；分别给出实际记录，不能统称“已复现” |

源码作者、数据准备者或此前参与同一试点的代理仍可提供有用的方法复核，但必须保留参与声明。对自身实现的核查、换一个代理审阅、同一数据上重复运行和独立采集证据，是不同事项。

## 六阶段与八个审阅轴

八轴 ID 与 [`SEMANTIC_REVIEW_AXES`](../sle/discovery_review.py) 一致；下表映射对应导出器的 [`STAGES`](../sle/discovery_review_packet.py)。阶段与轴不是一对一关系；同一条判断可以关联多个阶段，但不重复计分。

| 发现阶段 / packet ID | 主要审阅轴 | 这一阶段要回答的问题 |
| --- | --- | --- |
| 问题 / `question` | `scientific_question` | 对象、问题和适用范围是否明确？拟解决的不确定性是什么？ |
| 竞争假设 / `competing_hypotheses` | `hypothesis_operationalization`、`competing_explanations` | 假设及条件能否被已声明的观测检验？替代解释是否实质而非方便击败的比较项？ |
| 实验或推导 / `experiment_or_derivation` | `experimental_rationale`、`uncertainty_and_selection` | 工具、测量或推导为何能区分这些解释？计划、选样和判据何时固定？ |
| 证据 / `evidence` | `hypothesis_operationalization`、`reproducibility`、`uncertainty_and_selection` | 引用究竟来自哪项观测或工件？来源、误差、复用和缺失情况是否支持当前用途？ |
| 检验（必要时修订） / `testing_and_revision` | `inference_warrant`、`competing_explanations` | 原预测遇到什么支持、反证或不可判断结果？候选是否在协议允许的阶段作了合理回应？ |
| 有适用范围的结论 / `scoped_conclusion` | `inference_warrant`、`novelty_and_scope` | 最终说了什么、依据何在、还不能说什么？新颖性声明是否有相应证据？ |

每个轴至少核对以下资料。此表列出审阅所需信息，不表示当前 episode 已经提供。

| 轴 ID | 需要定位的材料与审阅重点 |
| --- | --- |
| `scientific_question` | 公开问题、假设 ID、相关领域文献；说明问题意义和范围的依据，而非只复述题面 |
| `hypothesis_operationalization` | 假设版本、检验 ID、测量定义、假设条件检查；逐项解释观测量如何对应主张，复合主张哪些必要部分仍未检验 |
| `competing_explanations` | 所有声明的替代解释、预测及相关文献；逐对查看相同、重叠和分离的预测，记录尚无法区分的解释 |
| `experimental_rationale` | 计划、原生证据、对照与校准记录；审查设计理由、混杂、选样和实际执行是否对应 |
| `inference_warrant` | 主张、原生支持与反证、检验和修订版本链；涉及因果时定位识别论证；数值相容不能独自证明整项推断 |
| `uncertainty_and_selection` | 采样设计、测量误差、选择过程、重复检验及不确定性方法；明确区间是什么，未验证的误差方法不能被表述为已验证精度 |
| `reproducibility` | 工具参数、数据与运行时绑定、分析工件、复核来源；分别判断能否重放、是否实际重放以及复核数据是否独立采集 |
| `novelty_and_scope` | 主张、限制、实际核查的文献及声称的外部验证；区分任务内重发现与领域新知识，记录检索范围和未核查部分 |

未提供文献时不能给新颖性结论；缺乏采集来源时不能推断独立性；没有实际代码重放记录时不能把“可读取代码”写成“已复现”。若需补查外部资料，应记录实际查到的出处和支持范围；本模板自身不提供学科事实或预设科学答案。

## 每条判断的最小记录

一条判断只评价明确的主张或过程事项。下表可作为人工审阅条目模板；具体机器字段以导出的 packet 为准，不要求直接把此表导入 CLI。

| 字段 | 填写要求 |
| --- | --- |
| 阶段与轴 | 指明六阶段中的位置和八轴 ID；不将某一轴意见推广到全部发现质量 |
| 判断对象 | 精确到假设 ID 与版本、主张、检验、证据或候选解释条目 |
| 状态 | 初始为 `unassessed`；完成明确范围内的审阅时可记录已审阅及实际判断，但不写成统一“通过”或数值分数 |
| 原始定位 | 文件字节 SHA-256、报告摘要、JSON Pointer、事件 `seq`/摘要；按需补假设 ID、检验 ID、外层 `experiment-XXXX` 和代码工件位置 |
| 支持依据 | 逐项说明哪些已查看的记录支持这条判断；记录与推断分开，不以摘要或候选自述替代原生观测 |
| 反证与替代解释 | 定位全部相关的不相容、缺样本、失败和冲突结果，说明它们如何影响判断；尚存替代解释不能省略 |
| 缺项 | 缺少什么、为何影响可判断性；资料不足保持 `unassessed`，并写明所需材料，不自动填“无问题” |
| 判断理由 | 用可检查的公开论证把依据、反证和结论连接起来；不要求私有推理轨迹，不按文字长度评价 |
| 适用范围 | 对象、时期、条件、测量或推断层级及推广限制；指出该判断没有覆盖的事项 |
| 审阅者与版本 | 关联身份声明、时间、角色和修订记录；新意见追加保存，旧意见不覆盖 |

定位示例仅说明格式：`episode.json` 的原文件 SHA-256 加 `/events/12/payload/observation`，再关联该事件实际的 `seq`、检验 ID 与外层证据 ID。这里的 `12` 不是任何真实评测引用；填写时必须核对实际内容。源报告内的内容摘要与整个文件的字节摘要分别记录，不混用。哈希能够绑定所引用的内容，不能认证采集来源或科学正确性。

“未发现反证”须同时说明查看了哪些相关检验；没有查看、没有执行或结果不可用，不能写成反证不存在。程序自动收齐反证，只证明反证进入了结果包；候选是否理解并回应反证，需要候选实际解释及独立审阅。

## 协议可用性与公平归因

先看协议提供了什么机会，再评价候选行为。缺项归因与科学判断分开。

| 情况 | 记录方式 |
| --- | --- |
| v1 在检验前冻结 dossier，检验结束后没有候选解释阶段 | Packet 的 `posttest_interpretation.record_availability` 为 `not_available_in_protocol`；检验后解释、最终反证响应与相关修订项保持 `unassessed`，不能记为候选拒绝回应或推理失败 |
| v2 有只读解释阶段，但未收到有效解释 | 记录是否因预算、传输、基础设施、格式拒绝或候选未提交而缺失；定位相应事件。科学解释质量保持 `unassessed`，不从技术失败推出科学失败 |
| 观测缺样本、测量失败或结果无法提取 | 保留检验及失败记录，说明哪些预测无法判断；不把不可用观测算作支持或反对 |
| 有反证，候选撤回、缩小结论或保留不确定性 | 审阅其回应是否有依据且范围合理，不因未产出正向发现而扣成失败 |
| 候选不修订，保留原主张 | 审阅其理由和反证处理；不为展示修订而要求改变结论 |
| 空发现或两种预测都未获支持 | 允许有边界的空结论，审阅是否诚实覆盖已执行检验；空分母不构造成功率，也不构造科学零分 |

v1 的检验前标签与 broker 检验后状态处于不同时间点；二者不一致不能直接评价候选的检验后判断。v2 的“列出全部检验”是覆盖事实，不是理解分数。探索背景证据、前瞻预测检验和独立采集复核的角色分别核对；已经暴露的观测不能因更换协议、审阅者或 episode 名称而变成新的前瞻证据。

## 只读 packet 的使用流程

### 手工审阅练习

下面六项是方法审阅练习，数值由人工任意构造，不来自真实试点或已见封存数据。它们没有运行新的模型评测，也不是领域科学 GT；主要机器边界已经在既有协议测试中覆盖。可以把同一证据配上谨慎解释与过度断言，检查审阅意见是否有精确依据，不能据此声明审阅者已经通过认证。

| 手工记录 | 机器可核查的边界 | 尚需科学审阅 | 有限结论与应避免的越界 |
| --- | --- | --- | --- |
| 三项预测为 `[-8,8]`、`[-6,6]`、`[12,14]`，观察为 `2` | 前两项相容、区间重叠；不能把区分第三项写成区分全部 | 区间依据、替代解释合理性及测量不确定性 | 可说前两项尚不能区分；不能认定第一项是唯一机制 |
| H 要求 `A all_of B`，A 的 `[2,4]` 包含观察 `3`，B 没有检验 | 必要条件 B 缺失，整体前瞻相容未判定 | 主张分解是否忠实，是否还有未列条件 | 可说只检验了 A；不能说 H 整体成立 |
| 同一必要条件预测 `[2,4]`，两次观察为 `3`、`8`，后者进入预先登记的反驳区间 | 保留两项结果，不能用一次相容抵消另一必要条件失败 | 测量可比性、校准与结果的推广范围 | 可说第二次未保持该数值条件；不能直接断言总体机制不存在 |
| 先读固定行，再登记预测并重测同一来源 | 登记顺序、来源复用和背景/前瞻角色 | 来源描述完整性、衍生数据依赖与选样影响 | 可作探索性描述；不能当作新前瞻支持或独立复现 |
| 预测不相容后提出“仪器漂移”，并收窄结论 | 原记录保留，新解释为 `posthoc_unvalidated` | 新解释的依据、是否解释全部反证及是否移动判据 | 可列待检验解释；不能说漂移已被本轮验证 |
| 测量不足：一份完整提交空发现；一份 v2 没有最终解释 | 分别记录响应覆盖和缺失；v1 缺解释须另记协议不可用 | 空结论是否诚实反映现有证据；缺失解释不评其质量 | 前者可保留不确定性；后者只说明交付缺失，不补科学零分 |

### 导出与填写

使用私有的原始 episode 生成审阅准备材料：

```sh
python scripts/prepare_discovery_review.py \
  --episode /private/operator/episode.json \
  --output-dir /private/operator/review-packet
```

输出为 `review-template.json`，包含 `source.report_sha256` 和 `source.file_sha256`。阶段引用使用 `report_pointer`、`event_kind` 和 `event_sha256` 定位原报告的 `/events/N`，不复制私有测量值或候选分析代码。各阶段的 `record_availability=recorded/not_recorded` 只说明是否有相应记录，阶段与八轴的 `judgment.status` 均初始化为 `unassessed`；有记录不表示行为正确或阶段成功。

导出器只提供原记录的定位与空白审阅字段，不自动填写科学结论，不调用模型，不运行候选代码，不读取额外封存数据，也不重新执行或改写历史评测。它会运行已有的结构重放检查，结果仅保存在过程层。准备材料不构成新评测批次或新的付费调用授权，当前也没有填写后审阅的导入或认证功能。

1. 固定原报告及其摘要，核对 packet 所指的同一份原件；结构检查是否通过只记在过程层。
2. 填写审阅者声明，先标出协议可用性、已获得材料和缺项。审阅者只在实际可判断的范围内填写意见。
3. 按六阶段查看问题到结论的证据链，再按八轴检查遗漏。每条意见均回到原记录，不只阅读派生指标。
4. 分层另存填写后的审阅副本和补充材料，绑定源报告、原 packet 摘要及审阅版本；原始 episode 与空白模板保持原样，不将外部意见回填为历史 `semantic_review`。填写后的副本是新工件，必须重新计算自己的摘要；不得沿用模板的顶层 `sha256` 并声称仍与修改后的内容匹配。
5. 若审阅者意见不同，保留各自依据、范围和身份声明，将争议单独列出，不平均成分数。没有完成独立领域审阅的轴继续明确为 `unassessed`。

Packet 含有指向私有记录的引用，原件和填写后的审阅资料应由操作者保存在私有位置；公开方法说明不能顺带发布凭证、私有观测或候选不可见材料。后续若实际重放分析，须单独记录所用源码、运行时、输入、输出和 Linux 隔离执行证据，不能将本次只读准备标记为重放完成。

相关约定见[发现定义与评估](discovery_evaluation.md)、[检验后只读解释协议](discovery_posttest_v2.md)和[首轮真实观测试点记录](discovery_observational_pilot_results_20260920.md)。

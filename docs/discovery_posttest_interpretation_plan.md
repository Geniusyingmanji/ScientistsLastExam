# 封存检验后的只读解释阶段：实现计划

**状态：尚未实现。** 本文提出下一版协议，不描述当前运行时已经具备的能力。
当前源码 `21746eaf1c1d1edf2802b6066203aa98c7b22752` 对应的冻结 round 保持原样：不改研究计划、不补模型调用、不重跑、不重算历史指标。
本计划衔接 [Discovery 定义与评估](discovery_evaluation.md) 和 [真实观测试点](discovery_observational_pilot.md)。

## 为什么追加一个阶段

目标流程为：**问题 → 竞争假设 → 实验或推导 → 证据 → 检验（必要时修订）→ 有适用范围的结论**。
当前协议先冻结包含结论的 dossier，再执行封存检验，之后直接结束。因此候选尚无机会根据检验结果作最终解释。
固定策略在检验前诚实声明 `inconclusive`，而检验后 ledger 得到 `rejected`，属于不同时间点的判断。
此时 `conclusion_matches_operational_checks=false` 不能直接解释为模型能力失败或候选无视反证。
本轮的 `counterevidence_disclosure=2/2` 表示 broker 自动纳入了全部反证，不能算作候选读过结果后主动处理了反证。

## 两次冻结与阶段边界

拟议新版本使用以下状态；必须有明确协议版本，不能改变旧报告字段的历史含义。

```text
exploring → test_plan_committed → testing → interpreting → finalized
```

1. `exploring`：保留多轮观察、分析、竞争假设、研究理由和版本化修订；探索后形成的预测不追认探索证据为前瞻验证。
2. `test_plan_committed`：第一次冻结。绑定问题范围、所有假设版本、预测区间、反驳条件、工具参数、选样规则、完整检验列表和检验前判断。
3. `testing`：可信 broker 按冻结计划执行全部封存检验，保存原生证据、收费记录、数据与源码绑定；缺样本或工具错误也保留。
4. `interpreting`：候选获得完整检验结果包，作只读解释。结果包只含本计划获准返回的观察，不开放其他封存行或新查询。
5. `finalized`：第二次冻结，保存候选的最终解释、结论范围和修订理由。此后不再接收修改。

第一次冻结记录、全部检验结果和最终解释是三个分别有哈希的追加式记录，最终解释必须引用前两者。
保留检验前判断以评估校准和预测；最终解释不能覆盖旧判断、失败预测或任何反证。
检验仍只判断操作性预测与观测的关系，不引入隐藏 GT、已知机制标签或统一科学发现总分。

## 解释阶段的动作边界

以下为待实现动作约定，不是当前 CLI 已支持的命令。

| 动作 | 是否允许 | 约束 |
| --- | --- | --- |
| 阅读完整冻结计划与结果包 | 允许 | 只能读取已完成且获准返回的记录；同一结果不重复计为新证据 |
| `submit_interpretation` | 允许一次 | 提交最终结论、逐项检验响应、证据引用、限制与修订理由后结束 |
| 登记或执行新的实验、推导工具、数据查询 | 禁止 | 无新增观察，不允许挑选别的分组、阈值或时间窗口重试 |
| 修改原假设、预测、反驳条件或选样规则 | 禁止 | 原记录只读，任何变化不得重新计算为原计划成功 |
| 执行新的 `analyze` 代码 | 最小版本禁止 | 先用已返回的观察完成解释，避免扩张执行与审计范围 |
| 重新提交最终解释或重开 episode | 禁止 | 第二次冻结后保持关闭 |

最小版本无需增加检验后的实验循环。若确实需要新实验，应另建事前冻结的研究计划，使用未暴露的新证据并另行安排预算。

## 最终解释必须包含什么

- 引用冻结计划与完整结果包的哈希，列出所有封存检验 ID 及对应原生证据 ID；不得只呈现相容的子集。
- 对每项检验分别说明相容、不相容或无法判断，以及对原主张的影响；缺样本、失败和反证都不能省略。
- 明确最终判断、适用对象与条件、仍未解决的替代解释、不确定性和推广限制。
- 如保留原主张，说明反证为何不改变限定后的主张；如否定或缩小范围，明确引用被修订的原版本与理由。
- 检验后新提出的假设只进入独立的事后假设列表，标记 `posthoc_unvalidated`；不得进入本轮获得前瞻支持的主张集合。

最终结论允许“原预测未获支持”“两种竞争预测均不相容”“现有数据不足以区分解释”或无发现。
两种预测均失败不意味着必须选一个获胜，也不自动识别具体机制；缩小范围后的主张同样不能自动获得新的验证资格。
空发现合法：可提交无新知识主张的最终解释，并如实处理已经执行的检验。没有检验时相关分母为零的指标返回空值。
保留原主张也合法，不为展示修订而强迫改变结论；评价依据是对证据的合理响应。

## 分开记录 broker 与候选质量

| 层面 | 自动记录或核查 | 不能据此声称 |
| --- | --- | --- |
| Broker 完整性 | 计划执行覆盖、结果包完整性、证据真实性、冻结边界、全部反证是否可供阅读 | 候选已理解或主动回应反证 |
| 原预测表现 | 每个冻结预测的相容性、区分力、证据是否前瞻、测量可用性 | 科学真理、因果成立或创新性 |
| 候选解释过程 | 是否实际提交解释、是否覆盖全部结果、引用是否合法、修订来源是否明确、事后假设是否标注 | 仅靠列满 ID 就获得科学推理质量分 |
| 独立科学审阅 | 反证处理是否合理、推断是否成立、限制是否充分、替代解释与新颖性 | 自动从字段齐全或文字长度推断审阅通过 |

新增候选响应指标使用独立字段，不能复用当前 `counterevidence_disclosure` 冒充候选表现。
最终结论与操作性检查的一致性仅作诊断；解释是否合理仍需独立审阅。未实施审阅时各科学质量轴保持 `unassessed`。
broker 生成的逐项结果覆盖，与候选提交的逐项响应，分别保存、分别计数，不互相代填。

## 预算与失败处理

下一轮必须在启动前声明解释阶段预算，并包含在每 episode **最多 32 次付费调用**内，不额外增加调用。
最小方案预留最后 1 次调用用于最终解释，研究阶段最多使用 31 次；在可用时间与实验预算内先冻结检验计划。
若未及时冻结、封存检验耗尽可用时间或解释调用失败，保留全部记录并标记解释未完成，不能再免费补一轮或偷偷使用第 33 次调用。
调用超时、provider 错误和缺失最终解释分别报告；不可一律写成科学发现失败。已执行预测检验仍保留其原有结果。
当前冻结 round 不采用此预算重分配；任何新版本运行需要新的明确运行计划，不能借协议升级重置已消耗配额。

## 验收中的失败场景

1. 看过封存结果后改预测区间或反驳条件：动作被拒绝，旧计划哈希和检验结果保持不变。
2. 只引用相容检验、遗漏一项反证或缺样本结果：最终解释覆盖检查失败，broker 不替候选补齐响应。
3. 伪造证据 ID、引用其他 episode 或篡改结果包哈希：提交被拒绝，不产生有效最终结论。
4. 在解释阶段请求新分组、新窗口、原始封存行或 `analyze`：被拒绝，不运行工具、不收集新证据。
5. 将检验后提出的解释标记为本轮已验证发现：不得获得前瞻性支持；保留事后来源并指出资格不符。
6. 两种预测都不相容，候选仍宣称其中一种得到确认：保留原预测失败，标出结论与证据的冲突供独立审阅。
7. broker 已自动纳入全部反证，但候选未提交解释：候选响应状态为未完成，不能继承 broker 的 2/2 完整性。
8. 检验前 `inconclusive`、检验后否定原预测并正确限定结论：不把前后标签变化判成推理失败，评估其证据响应。
9. 无发现或测量不足：允许有边界的空结论，不构造零分科学总分，也不把测量不可用归为模型能力失败。
10. 第 32 次调用超时、进程中断或最终提交重复：保留消耗及原始记录，禁止第 33 次调用和自动重复付费。

验收测试只使用手工 fixture 与模拟传输，不读取当前真实封存结果来调参；上线前需另行完成协议、隔离和报告重放测试。

## 首轮模型运行暴露的复合主张问题

2026-09-20 的两个有效 GPT-5.6-sol episode 进一步说明：仅追加解释阶段还不够。
当前 ledger 对同一主张出现支持与反对时统一返回 `inconclusive`，并不解析主张的逻辑。
例如“两个时期都弱”已被探索时期的描述性观察违背，不能被封存期相容的观察挽救；
“季节存在异质性且封存差变小”也不能只检验后一项就认定整体得到支持。
这些是对自报科学主张与操作性预测之间关系的审查，不需要隐藏的科学答案。

下一版在首次冻结前应允许显式分解主张，记录必要子主张、相应检验及它们的 `all_of` / `any_of` 关系，
并区分必要条件检验与足以支持完整主张的设计。未检验的必要部分必须显示缺口，
不能因另一部分相容而自动获得整体支持。该结构本身、科学主张是否被忠实操作化，仍需独立科学审阅；
不能让模型自行写出有利的逻辑表达式就获得科学质量认证。

数值区间内外、命中显式反驳条件、有限样本描述与总体推断应分别记录。
在没有有效不确定性方法时，跨过阈值不能自动解释为总体效应被统计证伪。
复合主张关系不明时，标记 `requires_semantic_review`；不要继续用投票式标签比较来判候选结论对错。
现有 `conclusion_matches_operational_checks` 留作旧版本诊断，不能作为科学正确率。

证据引用也应增加角色：背景观测、探索性诊断、事前预测检验、独立收集的复现。
原始探索数据可以是真实且相关的引用，却没有提供前瞻支持；应标记角色差异，不把这种引用等同于伪造。
所有预测的逐对可区分关系应可查看，不能把“至少区分一个替代项”的比例理解成“区分了全部竞争解释”。

新增验收场景：

11. `all_of` 的一个必要描述性条件不相容、另一个相容：保留各项记录，不以支持/反对相抵掩盖必要条件失败。
12. 仅执行复合主张的一部分检验：整体科学支持保持未判定，明确未检验的必要部分。
13. 两个竞争解释在现有检验上有相同预测：显示二者不可区分，不能因第三项预测不同而宣布两者已区分。
14. 合法探索观测只作为背景诊断引用：不赋予前瞻支持，也不错误标为伪造证据。

这些新增要求尚未实现；本轮的原始预测、报告、指标和全部 3 个已消耗槽位保持不变。

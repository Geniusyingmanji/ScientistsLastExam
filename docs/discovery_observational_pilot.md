# 无 GT 的真实观测试点：北京污染与风向的跨时间描述性检验

本试点落实 **问题 → 竞争假设 → 实验或推导 → 证据 → 检验（必要时修订）→ 有适用范围的结论**。它使用真实观测检验环境与研究方法；暂不声称题目困难、发现新知识、独立采样或识别因果机制。规律、结构、机制、物质是结论类型，并非必须逐级完成的步骤。检验支持原假设时不强迫修订。

## 数据与固定转换

数据为 Chen, S. (2015), *Beijing PM2.5*, UCI Machine Learning Repository，[DOI 10.24432/C5JS49](https://doi.org/10.24432/C5JS49)。[官方页面](https://archive.ics.uci.edu/dataset/381/beijing+pm2+5+data)明确提供 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 许可：2010–2014 年共 43,824 条小时记录，PM2.5 来自北京美国使馆站点，气象来自首都机场。此处 PM2.5 是观测量，不是科学假设的答案标签。既有论文结论不参与评分。

`scripts/prepare_beijing_measurement_pilot.py` 仅依赖标准库，下载官方 CSV，并在下载之前保存规则与脚本摘要。它执行以下固定规则：

1. 每年 1 月 1 日起按 168 小时形成不跨年的时间块；丢弃年末不足一周的块。要求该周全部 168 个唯一小时存在，且至少 126 小时有 PM 观测。`NA` 不插补，其他 PM 值须有限且非负；异常 ID、时间戳或风向使构建失败，不静默删除。
2. 2010–2012 为探索，2013–2014 为封存。任何与 `[2012-12-18, 2013-01-15)` 相交的整周都排除，形成边界两侧各 14 日隔离。隔离不保证剩余时间块独立。
3. 仅发布四列：`year`、`season_code`、`pm_mean`、`wind_regime`。季节按周中点编码 DJF=0/MAM=1/JJA=2/SON=3。NW 或 SE 占全部 168 小时至少一半且另一方向不足一半时分别编码 0、1；其他情况及 50/50 平局编码 2。均值基于非缺失 PM 小时。
4. 不提供同一量的均值/P90/多个派生变体，不把重复查询或重新编码当作新样本。覆盖率与原始行 ID 血缘保存在操作方私有审计文件中。

构建示例，输出路径必须尚不存在、无符号链接且位于所有 Git 工作树之外：

```bash
python scripts/prepare_beijing_measurement_pilot.py \
  --output /private/tmp/sle-beijing-pilot-20260920
```

根目录及 `bundle/` 权限为 0700，文件为 0600。根目录保存原始 CSV、官方许可页面快照、冻结规则、转换脚本快照、完整计数及逐块原始行血缘。`bundle/` **只能有 `manifest.json` 和 `measurements.csv`**，供可信 broker 加载。候选沙箱不得挂载整个根目录或 bundle，只能经 MeasurementAudit 工具接收允许的观察。脚本输出摘要与清洗计数，不打印封存数值、分组对比或科学结果；原始数据和私有审计文件均不得提交到仓库。

`preparation.json` 同时记录原始文件、转换脚本、冻结规则、血缘、CSV 和 manifest 的 SHA-256；排除按“不完整日历周 → 边界隔离 → 小时网格不完整 → PM 覆盖不足”排序，每个块只计一次原因。原始行数必须等于保留和各类排除行数之和。覆盖筛选仍可能带来非随机缺失偏差，不能因规则固定就忽略。

## 科学问题与本轮可检验范围

完整问题是：风向与污染的关联是否在考虑季节和时间变化后保持？竞争解释包括稳定关联、季节构成混杂、关系随时间改变。当前工具只能读取探索数据，以及对单列执行 `mean` 或按单个分组执行 `mean_difference`，因此**本轮只能检验合并周均值差的描述性跨时间表现**；它无法完成季节调整、同时按年份分组或因果识别。

可冻结的检验为 `pm_mean` 按 `wind_regime` 的 `[0,1]` 分组差，定义为 SE 组均值减 NW 组均值。阈值、竞争预测区间、缺样本处理和结果解释须在封存开启前固定。探索后的预测是对未来封存块的预注册，不能追溯为探索样本上的前瞻假设。若封存方向组样本不足，应报告不确定；不得改阈值或挑别的分组重试同一封存数据。

封存隔离仅针对本次运行的工具访问：数据公开且可能存在于模型训练中。2013–2014 仍是同一历史来源的留出检验，不是新实验或独立收集的复现。默认工具给出的 IID 标准误没有在此时间序列上获得有效性保证，不能用作显著性或机制成立证据。

## 分阶段评估

| 阶段 | 可自动核查 | 独立科学审阅 |
| --- | --- | --- |
| 问题 | 问题、对象、时期和可观测量有版本记录 | 问题是否有意义，范围能否由数据覆盖 |
| 竞争假设 | 假设版本、至少两项预测及登记顺序 | 替代解释是否真实竞争，预测是否能区分它们 |
| 实验或推导 | 工具、参数、预算与分析代码摘要；冻结先于封存 | 设计是否处理混杂、选择偏差和依赖结构 |
| 证据 | broker 原生 ID、文件摘要、观测和引用一致性 | 单位、估计对象、缺失和测量误差是否正确理解 |
| 检验及必要时修订 | 所有预注册检验均报告；反证、失败与修订可追溯 | 是否解释冲突并适当撤回、收窄或保留结论 |
| 有范围的结论 | 结论能关联具体证据、版本与限制 | 推论是否越界；新颖性和科学价值另行判断 |

不把这些核查平均为“科学发现正确率”，也不把动作次数、文字篇幅、完整 JSON 或宽泛预测区间当作科学能力。真实负结果和审慎的不确定结论可以具有方法价值；一律弃答不产生正向发现信用。

当前 broker 的血缘检查只认识派生 CSV 的行与列，**不会解析私有原始血缘 sidecar**。虽然本试点减少了冗余列，PM 覆盖选择、风向分类及日历仍有依赖，跨列的“未见信息”主张不能仅凭自动日志成立。须独立审阅原始行血缘；后续正式支持应把保守源范围纳入受验证的 broker 合约，并补充攻击性测试。

## 对照、难度与下一步

首轮固定策略只执行同样的合并差异检验，冻结数值预测后开启一次封存；它与模型共享工具、数据和预算。另保留无工具叙述、宽区间总是支持、总是不确定、隐藏失败检验等对照，用于检查协议是否奖励空泛结论。GPT 多次运行只代表重复代理运行，不能计作多次科学独立复现。

本次实现的真实数据对照为 `scripts/beijing_pilot_controls.py` 中的 `fixed_pooled` 和 `null`。
前者按探索差值固定预测容差 `±max(10, abs(difference)*0.5)`，与 `[-10,10]` 的近零预测竞争；
这不是置信区间。两种预测重叠时不强求可区分，探索或封存组样本不足时保留不确定。
其他反例仍是协议测试对照，没有全部适配为真实数据科学基线。

Linux 首轮入口为 `scripts/run_observational_pilot.py`。需配置明确的
`model: gpt-5.6-sol`、`wire: chat`、`stream: false` 和已授权的 matrixllm 端点；
凭证配置在仓库外，不复制进候选环境。输出上限每次 8000 tokens、请求上限 180 秒，
每个 episode 最多 32 个 action/传输尝试、600 秒和 20000 测量单位，最多三个模型 episode。
脚本额外执行上述两个无模型对照。

```bash
python scripts/run_observational_pilot.py \
  --data-bundle /var/tmp/sle-beijing-pilot-20260920/bundle \
  --llm-config /private/operator/matrix-gpt56.json \
  --campaign-dir /var/tmp/sle-beijing-cohort-20260920 --prepare-only
# 检查冻结计划后，使用相同参数去掉 --prepare-only 执行。
```

同一批次必须始终使用同一个 campaign 目录。开始的 slot 即占用名额，重启不重跑；
中断或传输失败记录会阻止自动追加调用，不能换目录重置配额。
每轮先核对冻结的观测数据、代码与配置，传输无自动重试；返回模型 ID、用量和失败分别记录，
未返回用量记为未知而非零。公开结果应引用实际完成记录，不能把调用失败视为科学能力低。
这些上限是首轮工程标定条件，尚未证明足以让顶级模型完成充分科学调查。

若简单固定策略已能覆盖本轮实质推理，该试点保留作协议回归，不进入难题榜；一次满分或一次成功不足以判断科学难度。进一步研究需要冻结的季节/年份分层检验、覆盖敏感性分析、依赖结构下的不确定性，以及真正额外的数据来源。新工具必须绑定全部使用的源行、列与选取规则，封存端只能执行事先冻结的计划；不能在看过结果后适配并重新包装成新发现。

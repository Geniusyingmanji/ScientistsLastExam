# Discovery：检验后的只读解释协议

`sle episode --evidence-protocol posttest-v2` 显式启用第二版协议。默认仍为 `v1`，既有 schema 1 报告及其指标含义保持原样；第二版另存 schema 2 报告。协议升级不修改、重算或补跑历史 episode，也不授权新的模型调用。

科学流程保持：**问题 → 竞争假设 → 实验或推导 → 证据 → 检验（必要时修订）→ 有适用范围的结论**。规律、结构、机制、物质是结论类型。流程保留检验，有理由时才修订；候选也可以诚实地提交无发现，未执行检验时不构造成功率。

## 两次冻结

探索阶段允许在预算内提出竞争假设、登记事前预测、观测与分析。`commit` 冻结研究计划及检验前判断，可信 broker 按冻结计划执行封存检验。

随后候选进入只读解释阶段，读取本计划已返回的完整检验结果。候选使用 `submit_interpretation` 提交最终解释，引用冻结计划与结果包的哈希，回应全部检验，并说明结论范围与限制。这是第二次冻结。原假设、失败预测和反证仍保留，最终解释不覆盖它们。

解释阶段禁止新实验、查询、假设登记、原计划修改和 `analyze` 代码执行。候选可以依据检验结果否定原预测、收窄结论或保留限定后的结论；新的事后解释不能被追认为本轮事前预测获得的支持。具体 JSON 字段以 episode 首个 observation 中的活动协议为准。

## CLI 与预算

第二版只用于 `--evaluation-mode evidence`。可使用：

- `--actions`：离线回放 JSON 动作数组。
- `--program`：隔离运行自包含的 `solve(context, act)`；程序通过 broker 动作提交计划和解释，或在提交计划后返回最终解释供 runner 提交。
- `--llm-config`：多轮模型交互；需要另行获得实际调用预算，选项本身不创建配额。

既有 `--baseline` 策略遵循第一版协议，第二版明确拒绝把这些策略重新标记为第二版。程序执行以及 `--analysis sandbox` 继续使用 Linux 隔离设施，不提供本机代码执行 fallback。私有观测包和凭证属于可信控制端，不进入候选沙箱。

第一版未指定 `--max-steps` 时仍为 64。第二版默认为 32，允许 2–32，最终解释包括在这个总额内；不能完成第 32 轮后额外申请第 33 轮解释。候选必须在研究阶段及时提交计划，为解释保留一步，并在共享的时间与实验预算内完成工作。程序或动作回放的一步对应一次 broker 动作，多轮模型的一次响应对应一次动作；传输超时等失败仍必须由运行批次单独保留调用及用量记录。

第二版模型路径使用独立的单次请求客户端，JSON 和 SSE 共用请求上限，不自动重试。开始的请求即占用额度，超时不退回；最终报告的 `model_transport` 分别记录开始请求数、失败数、上限和零自动重试。缺失响应的总用量与费用保持未知，不能用已返回的部分合计代替。这个客户端只约束单 episode 的当前进程，不是可跨进程重置的批次授权；另开进程、修复代码或切换协议都不能恢复首轮已用完的三个名额。

例如，在获准的 Linux 运行环境中回放人工 fixture：

```sh
python -m sle episode \
  --task MeasurementAudit \
  --evaluation-mode evidence \
  --evidence-protocol posttest-v2 \
  --actions /path/to/manual-actions.json \
  --max-steps 32 \
  --output-dir /var/tmp/private-posttest-fixture
```

输出目录必须在 Git 工作区之外、仅当前用户可访问，且不可覆盖已有报告。真实交互程序和模型应读取该次 `commit` 返回的绑定，不能猜测或借用其他 episode 的哈希。

静态 `--actions` 文件可以在 `submit_interpretation.interpretation` 的两个顶层摘要字段中使用以下显式占位符：

```json
{"plan_sha256": "$commit.plan_sha256", "results_sha256": "$commit.results_sha256"}
```

只有这两个精确字符串会被替换为同一 episode 已完成冻结的摘要；没有有效冻结时拒绝替换。其余解释、预测判断、引用和限制均由动作文件提供，不作代填。这个离线回放便利避免了“完整动作文件摘要又包含引用自己的最终解释摘要”的循环依赖。运行绑定仍记录原始完整文件的 SHA-256 和 `action_replay_substitutions=posttest_digest_placeholders_v1`，事件记录实际提交的动作。操作者应在 Git 之外保留原文件；摘要绑定内容，不认证证据来源。

## 评估边界

这里不使用隐藏答案，也不产生统一科学发现总分。无 GT 仍要求真实观测、证据来源和可检验预测。过程记录、操作性预测检验与科学审阅分开：

| 层面 | 可核查内容 | 判断边界 |
| --- | --- | --- |
| 过程与证据 | 冻结顺序、计划和结果绑定、引用来源、资源消耗、解释覆盖 | 哈希和字段完整不证明科学推理成立 |
| 操作性预测 | 数值预测与观测是否相容、复合主张中尚未验证的必要部分、成对竞争预测是否可区分 | 不能把部分检验相容变成完整主张得到科学认证 |
| 候选最终解释 | 是否回应检验与反证、如何修订或限定原判断 | 自动检查只记录结构与关系，不按文字长度打科学质量分 |
| 独立科学审阅 | 假设操作化是否忠实、推断与限制是否合理、替代解释和新颖性 | 未完成审阅时，科学质量轴保持 `unassessed` |

探索观察可以作为真实且相关的背景证据，但不会因被最终解释引用就获得前瞻支持。复合主张中的必要部分、证据角色和逐对假设区分，需要单独查看；“至少区分了一个替代项”不等于“已区分全部竞争解释”。操作性结构本身同样需要科学审阅，不能让候选自行声明的结构替代外部判断。

`commit.structures` 可声明平面的 `all_of` / `any_of`，每个组成条件指向已登记的假设与检验。`all_of` 的一个必要条件不相容时，其他条件的相容不能抵消它；必要条件尚无检验时，不能获得完整的前瞻相容标签。遗漏该条件的其他已登记检验会明确列出，并阻止挑选有利检验后获得完整标签。未经分解的主张保持 `undetermined`；当前不实现嵌套逻辑、概率校准或科学认证。

每次检验逐对列出预测区间相同、重叠或分离的关系；端点相接仍为重叠。这只表示该次测量上的预测关系，不替代统计效力或机制辨识。证据引用另存背景、探索和前瞻检验角色；即使证据 ID 真实，也不能给未被该检验针对的主张自动添加前瞻支持。

这一版的协议验证使用人工 fixture 和模拟模型，不读取已见真实封存值调参。首轮模型评测及其已消耗的三个名额保持冻结，详见[原始试点结果](discovery_observational_pilot_results_20260920.md)；设计动机与后续要求见[解释阶段计划](discovery_posttest_interpretation_plan.md)。
